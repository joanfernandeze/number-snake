# Android App (Phase A of monetisation) — Design

**Date:** 2026-10-04
**Author:** Joan Fernández Esmerats (with Claude)
**Status:** Approved section by section (structure; in-app behaviour; icon, signing, build and tests).
**Builds on:** the monetisation and Play launch audit (Claude Docs, 2026-09-30), which chose Capacitor
over a TWA because in-app ads need a WebView and the Google Mobile Ads SDK.

---

## 1. The monetisation project, decomposed

Monetisation with ads is four sub-projects, each with its own spec → plan → implementation:

| # | Piece | Depends on |
| --- | --- | --- |
| **A** | **Android app** (this spec): the game packaged with Capacitor, no ads yet | — |
| B | Ads: AdMob + EU consent; first the rewarded "Continue" after a death, later the capped interstitial | A |
| C | "Remove ads": a one-off purchase through Play Billing | B |
| D | Play launch: account, listing, privacy policy, Data safety, the closed test | A |

**Order:** A, then open the closed test at once (Play needs 12 testers for 14 continuous days on a new
personal account, and those days cannot be shortened), then B shipped as updates during the test,
then C once the interstitial is live.

## 3. Structure

- **`capacitor.config.json`** at the root: `appId` `com.numbersnake.game`, `appName`
  `Number Snake`, `webDir` `www`.
- **`npm run app`** copies `index.html`, `style.css` and `src/` into `www/` (git-ignored) and runs
  `npx cap sync android`. A test checks that `www/` holds every file `index.html` and the modules
  import (walking the `import` graph from `src/main.js`), so a forgotten file can never ship.
- **`android/`** is generated by Capacitor and committed. Target SDK 36 (Play's requirement for new
  apps since 2026-08-31). Portrait only.
- **Native or web.** `src/platform.js` exports `isApp()` = `!!globalThis.Capacitor?.isNativePlatform?.()`.
  Plugins are reached through `globalThis.Capacitor.Plugins` (Capacitor's bridge injects them), so the
  game keeps loading its ES modules directly with no bundler. On the web every app-only path is a no-op.
- Dependencies (npm, dev-time only for the web): `@capacitor/core`, `@capacitor/cli`,
  `@capacitor/android`, `@capacitor/app` (back button, minimise), `@capacitor/assets` (icons, splash),
  at their current stable versions.

## 4. Behaviour in the app

- **Pause** (app and web alike). When the page is hidden mid-run (a call, another app, a locked
  screen), the run freezes. Back on the page, a card like the goal card reads **Paused · Swipe to
  continue**; the next swipe or arrow key resumes, applying its direction, with the next move a full
  interval later (as at the start of a run). The paused time does not count towards the run's elapsed
  time, so a `time ≤ T` star is not lost to a phone call (`run.t0` moves forward by the paused span),
  nor towards `durationMs` in the telemetry. Music already pauses with the page.
- **Android back button**, decided by a pure function `backAction(state)` in `src/nav.js`:

  | State | Back does |
  | --- | --- |
  | The map is open | minimise the app (`App.minimizeApp()`) |
  | A run is moving | pause it (the same card) |
  | A run is paused, or not yet started (goal card / swipe to start) | back to the map; the run is abandoned: no game over, no telemetry, no analytics |
  | The end-of-run panel is open | back to the map |

- **Notch and system bars.** The app draws edge to edge; the HUD, the board and the panels keep to
  the safe area. `index.html` gains `viewport-fit=cover` and `style.css` pads `#app` and the overlays
  with `env(safe-area-inset-*)`. If the Android WebView reports zero insets under edge-to-edge, use
  Capacitor's own edge-to-edge margin handling instead; the plan pins which after checking it in the
  emulator.
- **Analytics.** The Worker accepts the app's origin, `https://localhost` (Capacitor's default on
  Android), besides GitHub Pages and local `http://localhost`. **The Worker must be redeployed
  before the closed test**, or every app run is rejected silently.
- **Audio.** Effects and music work in the WebView as on the web; the first swipe is the gesture
  that unlocks audio.

## 5. Icon, signing, build

- **Icon.** `assets/icon.svg`, drawn in the game's colours: three snake segments (2, 4, 8 in their
  tile colours) turning a corner on the board's dark blue, eyes on the head, no text. The author
  approves it before use. `@capacitor/assets` generates the adaptive icon, the 512 px store icon and a
  plain dark splash with the icon from it.
- **Signing.** The upload key is created by the author in Android Studio (Build → Generate Signed
  App Bundle → create a new keystore); passwords never pass through Claude. `.gitignore` excludes
  `*.jks`, `*.keystore` and `keystore.properties`. Play App Signing is turned on in Play Console, so a
  lost upload key can be reset.
- **Build.** For testing, Claude builds a debug APK with Android Studio's bundled JDK
  (`android/gradlew assembleDebug`, no signing) and installs it on an emulator or on the author's phone
  over USB. The signed release AAB for Play is built by the author with the Android Studio wizard.
  Version 1.0.0, versionCode 1.

## 6. Testing

- **Node:** `www/` completeness (§3); `backAction` for every row of the table (§4); the pause
  bookkeeping as a pure helper (shifting `t0` by the paused span; elapsed time excludes it).
- **Emulator or phone:** the app starts on the map; play a run; leave to another app and come back
  (paused card, swipe resumes, no instant death); the back button in each state; nothing under the
  notch or gesture bar; music and effects play; a run reaches the Worker (`/stats` count rises).

## 7. What the author does

- Install the Android SDK platform 36 in Android Studio (SDK Manager) — build-tools 36 is already there.
- Redeploy the analytics Worker after the origin change (`cd analytics; npm run deploy` in PowerShell).
- Create the upload keystore and build the signed AAB (steps written down in the plan).
- Phase D (separate spec): the Play developer account (25 USD, identity check) and the closed test.

## 8. Not in this pass

Ads and consent (phase B); purchases (phase C); the store listing, privacy policy and Data safety
(phase D); iOS; a pause button on screen (back and leaving the app are the ways in).
